# Pruebas automatizadas — RF-14 Prevención de colisiones de archivos

## Alcance

- **Requisito:** RF-14 — no sobrescribir documentos existentes; añadir sufijos `_v2`, `_v3`, etc.
- **Aplicación:** `construccion-web`.
- **Componente:** `src/lib/document-storage.ts` (`writeLocalPdf`, `readLocalPdf`, `listLocalFolder`, `sanitizePdfFileName`).
- **Requisitos no funcionales relacionados:** RNF-14 (no exponer secretos al cliente) no aplica directamente a la elección del nombre; estas pruebas cubren la persistencia local y la integridad de los bytes.
- **Aislamiento:** cada caso utiliza una carpeta temporal aislada y la elimina al terminar.

## Casos de prueba

| ID | Tipo de prueba | Funcionalidad verificada | Criterio de verificación | Automatización |
|---|---|---|---|---|
| CP-RF14-01 | Unitaria (de componente) | Normalización del nombre | Sustituye caracteres no válidos y garantiza la extensión `.pdf`. | `unitaria limpia caracteres no validos y conserva la extension PDF` |
| CP-RF14-02 | Integración | Persistencia local | El PDF se escribe, se lee con el mismo contenido y aparece en el listado. | `integracion escribe, lee y lista un documento local` |
| CP-RF14-03 | Funcional | Primera colisión | La segunda carga usa `_v2` y conserva el contenido original y el nuevo. | `funcional agrega el sufijo v2 y mantiene ambos contenidos` |
| CP-RF14-04 | Rendimiento/estrés | Lote de archivos | 250 nombres distintos se almacenan en menos de 10 s. | `rendimiento almacena doscientos cincuenta archivos distintos` |
| CP-RF14-05 | Aceptación automatizada | Colisiones sucesivas | Tres cargas generan el nombre original, `_v2` y `_v3`, con los tres contenidos intactos. | `aceptacion preserva las tres versiones con el mismo nombre` |
| CP-RF14-06 | Integración | Aislamiento de rutas | Un identificador de archivo fuera del espacio local se rechaza. | `integracion rechaza una ruta codificada fuera del espacio local` |

## Ejecución y resultado

```bash
npx tsx --test tests/rf14-local-file-collision.test.ts
```

GitHub Actions ejecuta la suite y el lint de los archivos implicados en `.github/workflows/pruebas-rf-14.yml`. La suite es headless; Actions conserva la salida de pruebas como evidencia y no genera captura de pantalla de interfaz.

**Resultado local:** 6/6 casos aprobados con Node 24.15.0; duración total observada: 283 ms. El lote de 250 escrituras locales tomó 50,11 ms.

## Límites

La suite valida el proveedor local y el algoritmo de colisiones. No prueba Google Drive, almacenamiento remoto ni concurrencia de varias instancias escribiendo simultáneamente el mismo nombre.
