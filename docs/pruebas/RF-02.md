# Pruebas automatizadas — RF-02 Desactivación lógica de cuenta

## Alcance

- **Requisito:** RF-02 — desactivar una cuenta sin eliminarla físicamente, conservando historial y trazabilidad.
- **Aplicación:** `construccion-web`.
- **Componente:** `src/lib/user-status.ts`.
- **Requisitos no funcionales relacionados:** RNF-06 (no repudio y responsabilidad). Las pruebas verifican la creación de la entrada de auditoría en el flujo de servicio.
- **Aislamiento:** el cliente Prisma se sustituye durante cada caso por una transacción en memoria; no se conecta a una base compartida.

## Casos de prueba

| ID | Tipo de prueba | Funcionalidad verificada | Criterio de verificación | Automatización |
|---|---|---|---|---|
| CP-RF02-01 | Unitaria (de componente) | Validación del payload | Acepta exclusivamente un booleano `isActive`; rechaza tipos y campos inesperados. | `unitaria valida el cuerpo y solo admite un booleano isActive` |
| CP-RF02-02 | Integración | Desactivación y auditoría | La cuenta conserva su ID, cambia a inactiva y registra `USER_DEACTIVATED`. | `integracion conserva la cuenta y audita la desactivacion` |
| CP-RF02-03 | Funcional | Repetición idempotente | Solicitar una desactivación ya aplicada no crea otra auditoría. | `funcional no registra una transicion cuando la cuenta ya esta desactivada` |
| CP-RF02-04 | Rendimiento/estrés | Lote de transiciones | 250 cambios se procesan con el doble transaccional en menos de 5 s y cada cambio queda auditado. | `rendimiento procesa doscientas cincuenta transiciones simuladas` |
| CP-RF02-05 | Aceptación automatizada | Ciclo desactivar/reactivar | Se conserva la misma identidad y quedan dos acciones de auditoría ordenadas. | `aceptacion permite reactivar la misma identidad y preserva ambas auditorias` |
| CP-RF02-06 | Integración | Protección de administradores | Una cuenta `ADMIN` no puede desactivarse y no produce auditoría. | `integracion rechaza cambios de estado para cuentas administradoras` |

## Ejecución y resultado

```bash
npx tsx --test tests/rf02-user-status.test.ts
```

GitHub Actions ejecuta la suite y el lint de los archivos implicados en `.github/workflows/pruebas-rf-02.yml`. El lint global actual presenta errores en otras rutas; por eso el workflow verifica el alcance de este cambio. La ejecución es headless; la salida de pruebas de Actions constituye la evidencia automatizada y no se genera una captura de pantalla de la interfaz.

**Resultado local:** 6/6 casos aprobados con Node 24.15.0; duración total observada: 288 ms. El lote de 250 transiciones simuladas tomó 4,31 ms.

## Límites

La integración utiliza un doble transaccional en memoria. No valida el comportamiento de MariaDB/Prisma en una base real, el rendimiento de consultas de producción, la visualización del estado en el navegador ni la retención append-only de siete años de RNF-06.
